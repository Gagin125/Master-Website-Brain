## Core Lesson

This video is a practical layout library.

The main lesson is not "copy these layouts." It is:

> Build a personal library of layout patterns, understand what each pattern is good for, then adapt the pattern to the content and goal of the project.

The creator shows 3-column, 4-column, and 5+ column layouts, but the deeper idea is that columns are not just visual decoration. They are information architecture.

## Design Process Before Layout

### 1. Build inspiration before the project begins

The creator starts every project with a Figma file full of inspiration:

- screenshots,
- layout references,
- color references,
- typography references,
- image ideas,
- style-scape experiments.

Important point:

> The search for inspiration should not start when the client project starts.

Future application:

- Keep a running swipe file.
- Save full websites and individual sections.
- Save layout patterns separately from visual style.
- Save links back to the original sites.
- Collect inspiration daily so future projects do not start from nothing.

### 2. Use style-scapes as proof of concept

Before building the full website, the creator explores:

- colors,
- typography,
- images,
- section mood,
- graphic elements,
- layout direction.

This gives a proof of concept without committing to a complete design.

Reusable rule:

> Style-scapes help test whether the visual language fits before investing in the full website.

## Three-Column Layouts

Three-column layouts are best when showing three distinct ideas side by side.

Good use cases:

- feature comparison,
- testimonials,
- service options,
- pricing tiers,
- payment/subscription levels,
- team members,
- three-step processes,
- breaking up content-heavy sections.

Warning:

> Three columns can become intimidating if spacing is too tight or each column contains too much information.

### Pattern 1: Diagonal image rhythm with central focus

Observed example:

- headline and CTA above,
- images spaced diagonally,
- center image acts as the main character,
- side images act as supporting characters,
- animation helps focus attention as the user scrolls.

Why it works:

- diagonal placement creates movement,
- central image creates a focal point,
- supporting visuals prevent symmetry from feeling static,
- motion reinforces attention.

Use this for:

- product storytelling,
- hospitality/lifestyle sections,
- brand moments,
- portfolios,
- sections where one visual should dominate.

Implementation rule:

> In multi-image layouts, decide which image is the main character before placing the supporting images.

### Pattern 2: Three equal cards

Observed example:

- three cards in a row,
- each card has image/text/details,
- size and contrast guide the eye,
- useful for team or feature sections.

Why it works:

- predictable comparison,
- easy scanning,
- balanced rhythm,
- each item has its own container.

Use this for:

- team,
- testimonials,
- services,
- pricing,
- feature groups.

Warning:

Equal cards can become generic. Add interest through:

- typography,
- image treatment,
- subtle rotation,
- varied card heights,
- icons,
- strong content hierarchy.

### Pattern 3: Rotated or playful cards

Observed example:

- cards remain in a row,
- slight rotation creates visual energy,
- animation can make the cards feel interactive.

Why it works:

- keeps the familiar card system,
- adds personality,
- prevents layout from feeling too rigid.

Use this for:

- creative brands,
- education/course modules,
- portfolios,
- playful product sections.

Warning:

Rotation should be subtle. Too much makes the layout feel amateur or hard to scan.

### Pattern 4: Bento box with mixed column logic

Observed example:

- top row and bottom row use different spacing,
- one colorful box becomes the focal point,
- supporting cards surround it.

Why it works:

- combines structure and variety,
- allows prioritization,
- visually separates main idea from secondary ideas.

Use this for:

- feature lists,
- SaaS benefits,
- product capabilities,
- dashboards,
- "why choose us" sections.

Warning:

> Bento boxes fail when every box has equal emphasis.

Always decide which box should be seen first.

### Pattern 5: Asymmetrical white-space layout

Observed example:

- lots of white space,
- information is spread out,
- asymmetry keeps it visually interesting.

Why it works:

- dense information feels less intimidating,
- space creates elegance,
- layout feels custom rather than template-like.

Critique from video:

- text can become too small,
- buttons can become too weak if they are ghost buttons.

Reusable rule:

> White space can make information feel lighter, but typography must remain readable.

### Pattern 6: Single-column intro above three-column cards

Observed example:

- centered intro/headline first,
- three-column card layout underneath,
- one card uses contrast to become the focal point.

Why it works:

- intro gives context,
- cards provide options,
- focal card can highlight guarantee, risk reversal, or key benefit.

Use this for:

- pricing,
- plans,
- service tiers,
- guarantees,
- onboarding paths.

### Pattern 7: Before/after or contrast blocks

Observed example:

- multiple ideas shown in one section,
- before is visually grayed out,
- after is visually emphasized,
- icons make bad/good obvious.

Why it works:

- comparison is immediately clear,
- contrast reduces explanation burden,
- users understand transformation quickly.

Use this for:

- before/after,
- problem/solution,
- manual/automated,
- old way/new way,
- pain/result.

Reusable rule:

> When showing transformation, make the difference visible before users read the text.

### Pattern 8: Bookended text with people looking toward copy

Observed example:

- images on left and right,
- central text in whitespace,
- people in photos look toward the central content.

Why it works:

- human gaze directs attention,
- images reinforce message,
- central text becomes the natural focal point.

Use this for:

- testimonials,
- mission statements,
- brand story,
- impact copy,
- community sections.

Reusable rule:

> If photos include people, their gaze should support the section's attention path.

## Four-Column Layouts

Four-column layouts are useful for:

- product cards,
- blog posts,
- portfolio items,
- events,
- course modules,
- feature grids,
- e-commerce categories.

Warning:

> Four columns get cluttered quickly. Spacing and typography must do the heavy lifting.

### Pattern 1: Sparse four-column layout

Observed example:

- four columns but not much text,
- lots of white space,
- sections are easy to scan.

Why it works:

- columns organize information without feeling dense,
- white space reduces intimidation,
- content feels calm.

Reusable rule:

> Having four columns does not mean every column must be packed.

### Pattern 2: Numbered course/module cards

Observed example:

- each card has a number,
- short heading,
- supporting text,
- course/module structure.

Why it works:

- numbers attract attention,
- sequence feels organized,
- users understand progress or package contents quickly.

Use this for:

- steps,
- packages,
- educational modules,
- process sections,
- multi-part offers.

### Pattern 3: Horizontal draggable/swipeable cards

Observed example:

- cards can be dragged/swiped,
- useful when there is a lot of optional information,
- reduces vertical scroll.

Why it works:

- lets motivated users explore,
- avoids overwhelming everyone,
- works well on mobile if swipe is obvious.

Warning:

Do not hide critical information inside a swipe-only layout.

Use this for:

- testimonials,
- optional case studies,
- gallery previews,
- secondary feature details.

Avoid for:

- prices,
- essential benefits,
- primary trust proof,
- required instructions.

### Pattern 4: Event cards / listing cards

Observed example:

- lots of event information,
- strong title contrast,
- CTA visible,
- details like time/address/price spaced clearly.

Why it works:

- users first identify the event type,
- then see details,
- then act.

Use this for:

- events,
- blog cards,
- product grids,
- classes,
- appointments,
- workshops.

Reusable rule:

> In listing cards, make the item identity and next action the two strongest elements.

### Pattern 5: Product/feature card grid

Observed issue:

- text and next row of images can sit too close,
- users may not know which caption belongs to which image.

Positive rule:

> In card grids, spacing must clearly show which text belongs to which image.

This is especially important for dynamic content.

## Static vs Dynamic Content

The creator makes an important distinction.

Static content:

- manually edited,
- predictable text length,
- controlled image count,
- easier to design tightly.

Dynamic content:

- blog posts,
- products,
- CMS content,
- user-added items,
- unpredictable text length.

For dynamic layouts, design for:

- longest likely title,
- shortest likely title,
- missing images,
- uneven text length,
- empty states,
- variable card heights.

Reusable rule:

> Dynamic layouts must still look good when content is full, short, missing, or uneven.

## Five-Plus Column Layouts

Five-plus column layouts are about structure and utility.

Good use cases:

- navigation,
- footers,
- link-heavy sections,
- service indexes,
- large product/category lists,
- editorial/news pages,
- dense directories.

Warning:

> If content is not grouped clearly, five columns become visual noise.

### Pattern 1: Many images with short labels

Observed example:

- treatment categories shown as image tiles,
- little text,
- visual recognition matters more than reading.

Why it works:

- many options become browsable,
- visual variety keeps attention,
- minimal text prevents clutter.

Critique:

- text over images must remain legible,
- image overlays may need opacity/color treatment,
- black-and-white-to-color hover can help.

Reusable rule:

> In dense visual grids, legibility must beat image drama.

### Pattern 2: Accordion for user-controlled detail

Observed example:

- multiple categories,
- first item open by default,
- users choose what to expand.

Why it works:

- hides information until needed,
- reduces initial overwhelm,
- lets users self-select interest.

Critique:

- vertical text labels are hard to read,
- once active, labels should become easier to read.

Use this for:

- FAQs,
- service categories,
- product specs,
- technical details,
- complex processes.

### Pattern 3: Nested column structures

Observed example:

- four high-level columns,
- each column contains internal sub-columns,
- could effectively become 12 columns.

Why it works:

- dense information stays organized,
- headings and contrast guide scanning.

Critique:

- remove duplicated explanatory text,
- make small arrows or links easier to click.

Reusable rule:

> Dense nested layouts need ruthless editing and obvious interaction targets.

### Pattern 4: Artistic/editorial asymmetry

Observed example:

- beautiful composition,
- brand iconography,
- strong style,
- but text is too small and too dense.

Why it works:

- memorable,
- emotional,
- visually original.

Why it can fail:

- poor readability,
- too much information in one area,
- users must work too hard.

Reusable rule:

> A beautiful editorial layout still needs readable hierarchy.

### Pattern 5: News/editorial grid

Observed example:

- Huffington Post style grid,
- many article choices,
- images/headlines pull attention,
- no single primary CTA.

Why it works for news:

- users arrive expecting to browse,
- any article click is acceptable,
- content discovery is the goal.

Why it does not work for most business sites:

- most businesses need one primary action,
- too many equal choices dilute intent,
- visitors may wander without converting.

Reusable rule:

> Dense editorial grids work when browsing is the goal. They usually hurt focused conversion pages.

### Pattern 6: Structured footer grid

Observed example:

- six-column footer,
- grouped information,
- visible grid lines,
- clear scanning.

Why it works:

- footers often hold many links,
- grouping reduces chaos,
- columns help users locate information quickly.

Use this for:

- e-commerce,
- restaurants with multiple links,
- service businesses,
- SaaS,
- directories.

## Mobile Layout Rules From The Video

For 3+ column layouts:

- mobile should not blindly stack everything if it creates endless scroll,
- optional cards can become horizontal swipe sections,
- important content should not be hidden,
- 4+ columns rarely make sense on mobile,
- two-column image grids can work when images are supporting, not critical,
- text should usually stay left-aligned for readability,
- spacing must clearly separate items.

Reusable rule:

> Mobile layout should reduce work, not merely preserve desktop structure.

## Layout Selection Guide

### Use 3 columns when:

- comparing three ideas,
- showing three tiers,
- explaining three steps,
- creating a balanced content section.

### Use 4 columns when:

- listing many similar items,
- showing products,
- showing events,
- showing course modules,
- showing cards where each item has equal weight.

### Use 5+ columns when:

- organizing dense information,
- creating footer/nav systems,
- building editorial/news layouts,
- showing many categories,
- browsing is the goal.

### Use bento when:

- one or two items need more emphasis,
- content has mixed importance,
- you want structure plus visual variety.

### Use accordion when:

- content is optional,
- categories are many,
- users should choose their path.

### Use horizontal swipe when:

- content is optional,
- mobile scroll length must be reduced,
- the section is not critical to every visitor.

## Rules To Remember For The AI Brain

- Do not choose a layout because it looks cool. Choose it because it fits the content job.
- Multi-column layouts need more spacing discipline, not less.
- Four columns can feel clean if the content is light.
- Dense layouts need grouping, contrast, and ruthless editing.
- White space can make multi-column content feel less intimidating.
- Card grids need clear ownership between image, text, and CTA.
- People in images should look toward important content.
- Ghost buttons are often weak when the goal is action.
- Dynamic content layouts must survive uneven content.
- Editorial grids are for browsing, not focused conversion.
- Mobile versions may need stacking, swiping, or simplification depending on importance.

## Practical Checklist Before Using A Layout Pattern

Ask:

- How many ideas does this section need to communicate?
- Are the ideas equal, or is one more important?
- Is the user comparing, browsing, learning, or acting?
- Is this content static or dynamic?
- Does the layout still work with long text?
- Does the layout still work with short text?
- What happens on mobile?
- Is any critical content hidden in a carousel or accordion?
- Is the CTA obvious?
- Are images helping attention or distracting from it?
- Does spacing show what belongs together?

## Strongest Principle From This Video

Layouts are reusable, but they are not universal.

The same 3-column, 4-column, or 5-column structure can feel premium, generic, overwhelming, or clear depending on:

- spacing,
- hierarchy,
- content density,
- image use,
- mobile behavior,
- and whether the section's job matches the layout.
