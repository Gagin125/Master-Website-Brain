## Core Lesson

Advanced layout is not about making pages weird.

It is about controlling the page:

- business goals,
- hierarchy,
- grid usage,
- visual journey,
- repetition,
- global alignment,
- white space,
- and intentional contrast.

The strongest idea from this video:

> The designer should control the grid, the canvas, and the story. The layout system should not control the designer.

## The 12 Layout Principles

### 1. Start with the business in mind

Design is solving a business and user problem.

Before opening Figma, define:

- primary website goal,
- secondary website goal,
- tertiary website goal,
- primary CTA,
- secondary CTA,
- modules needed to support the goal,
- pages needed to support the goal,
- copy needed to support the goal.

The layout should not be based on what looks cool first. It should be based on what the website must accomplish.

Reusable rule:

> Business goals dictate CTA hierarchy, module order, page structure, and story.

Example application:

- If the goal is reservations, the main CTA is reservation.
- If the goal is booking a call, the main CTA is application/contact.
- If the user may not be ready, the secondary CTA can be learn, view menu, see gallery, or read case studies.

### 2. Give meaning to every visual decision

The video separates junior design from art direction.

Junior thinking:

- choose trendy colors,
- choose fonts because they look cool,
- copy layouts from inspiration,
- decorate without conceptual reason.

Art-director thinking:

- Why this typeface?
- Why this color?
- Why this layout?
- Does the visual system connect to the brand, audience, and concept?

Beauty without meaning is only cosmetic.

Reusable rule:

> Every major visual decision should have a reason connected to the project.

### 3. Turn data into information

Data is raw.

Information is shaped, prioritized, and made understandable.

Designers should not dump content on the page. They should digest it and turn it into scannable, engaging, meaningful pieces.

Ways to turn data into information:

- extract key moments,
- create visual hierarchy,
- use badges or labels,
- separate stats from body text,
- highlight important details,
- create narrative pacing,
- break long text into digestible sections.

Reusable rule:

> Do not paste content. Interpret it.

This is especially important for:

- history pages,
- case studies,
- about pages,
- service explanations,
- menus,
- comparison sections,
- dense business pages.

### 4. Do not let the grid control you

A grid is a tool, not a cage.

The video recommends composing first, then using the grid to refine alignment.

Bad workflow:

1. Turn on grid.
2. Place every element mechanically.
3. Let the grid decide the layout.

Better workflow:

1. Explore the composition.
2. Find the visual rhythm.
3. Turn on the grid.
4. Adjust and formalize the layout.

Some elements may follow the grid. Others may be fixed, oversized, full-width, or outside the grid.

Reusable rule:

> The grid should support the composition, not flatten it.

### 5. Control the visual journey

A strong layout usually has one main visual hook, then a second and third hierarchy.

More than three dominant hierarchy levels can create confusion and cognitive load.

The user should understand:

1. What to look at first.
2. What to look at second.
3. What supporting detail matters third.

Reusable rule:

> Most sections should have one primary hook, one secondary element, and one tertiary detail layer.

Example:

- Primary: H1 or hero object.
- Secondary: image or CTA.
- Tertiary: supporting text, metadata, small labels.

If everything is visually loud, nothing is important.

### 6. Repeat more than you change

Sophisticated websites often repeat:

- typeface,
- color palette,
- spacing logic,
- background system,
- component rhythm,
- alignment,
- button style,
- section architecture.

The point is not to make every section different. It is to create enough consistency that the website feels intentional.

Reusable rule:

> Repeat the system. Change only where the story needs contrast.

This is why Apple-style pages feel polished: they change content, but the underlying visual language stays stable.

### 7. Unblock the whole canvas

Do not trap the page inside a narrow column if the full canvas is available.

This does not mean filling every inch with clutter. It means controlling the full viewport so the page does not feel like it is accidentally squeezed into the center.

Ways to unblock the canvas:

- let some images span wider,
- use full-width visual moments,
- place elements near edges intentionally,
- let large type occupy real space,
- use background zones,
- vary section width,
- align some elements to global rails instead of local cards.

Reusable rule:

> White space should feel intentional, not abandoned.

Important nuance:

Minimal pages can still control the whole canvas. The issue is not emptiness. The issue is unmanaged emptiness.

### 8. Do not marry the first iteration

Advanced layouts usually come from exploration.

The designer shows that the final result came after:

- copying and changing layouts,
- trying new colors,
- moving elements,
- testing arrangements,
- rejecting early versions.

The first idea is rarely the best idea.

Reusable rule:

> Iteration is not cleanup. Iteration is where the design becomes good.

For future work, create multiple layout options before locking in the first acceptable one.

### 9. Pick a few layout rails

Layout rails are global vertical alignment lines that run through the full page.

They help different sections feel connected.

Examples:

- headlines align to the same rail,
- images snap to the same rail,
- CTAs repeat on the same rail,
- labels share a recurring edge.

This creates a holistic page instead of isolated sections.

Reusable rule:

> Use two or three recurring alignment rails so sections relate to each other.

This is different from a full grid. Rails are simpler and often more editorial.

### 10. Use templates as the floor, not the roof

Templates can be useful starting points.

The mistake is stopping at the template.

A template may give:

- baseline structure,
- common section order,
- basic UX pattern,
- content skeleton.

But then the designer should push it:

- change the composition,
- place elements on borders,
- break the predictable left-text/right-image rhythm,
- introduce stronger hierarchy,
- use project-specific imagery,
- create a unique visual system.

Reusable rule:

> Templates can start the thinking, but they should not define the final ceiling.

### 11. Hook the user in the hero

The hero is the cover of the website.

It must be:

- visually powerful,
- clear,
- fast to understand,
- connected to the offer,
- and strong enough to make the user continue.

The hero should answer:

- What is this?
- Why should I care?
- What can I do next?

Hero hooks can come from:

- big typography,
- strong product image,
- real action photo,
- compelling cut-off text,
- interactive scroll cue,
- clear CTA,
- visible price/offer context,
- immediate brand atmosphere.

Reusable rule:

> A hero needs both impact and clarity. One without the other is weak.

### 12. Be intentional: be subtle or bold, not mild

This is the main law of composition from the video.

When making a visual decision, either:

- go clearly bold,
- or go deliberately subtle.

Do not make weak middle-ground changes that feel accidental.

Bold examples:

- huge type compared with body text,
- strong scale contrast,
- full-width image,
- dramatic layout shift,
- clear focal point.

Subtle examples:

- soft color contrast,
- restrained border,
- quiet typography,
- low-key background shift,
- small alignment detail.

Bad middle-ground:

- text only slightly bigger,
- color only accidentally different,
- spacing inconsistently larger,
- section contrast too weak to feel intentional.

Reusable rule:

> If the user can feel the decision but not understand whether it was intentional, the design feels weak.

## Visual Thinking From The Examples

The video repeatedly shows websites that feel advanced because they do one or more of these:

- use oversized type as a structural object,
- combine fixed and scrolling areas,
- use one strong visual hook per section,
- make long pages feel cohesive through repeated rails,
- use full-canvas control instead of narrow template stacking,
- turn raw content into editorial moments,
- use images, stats, copy, and CTAs as parts of one composition.

The examples are not just “cool layouts.” They are controlled systems.

## How Codex Should Apply This

When building future websites, Codex should ask internally:

- What is the primary business goal?
- What is the primary CTA?
- What is the section's first, second, and third hierarchy?
- Is this grid helping or controlling the design?
- Are we using the whole canvas intentionally?
- Are there global rails tying sections together?
- Are we repeating more than changing?
- Did we iterate, or did we accept the first layout?
- Is the hero clear and visually strong?
- Is each design move bold, subtle, or accidentally mild?

## What The Human/User Should Decide

The human should help decide:

- business goal priority,
- whether the page should feel safe, expressive, editorial, playful, or luxurious,
- what level of experimentation is appropriate,
- which visual choices feel true to the brand,
- when a template pattern should be kept for usability,
- when it is worth breaking convention.

## Practical Checklist

- Define primary, secondary, and tertiary goals.
- Match CTAs to those goals.
- Make visual choices explainable.
- Convert raw content into scannable information.
- Compose before forcing everything into a grid.
- Limit each section to about three hierarchy levels.
- Repeat core visual systems more than changing them.
- Use the full canvas intentionally.
- Try multiple layout iterations.
- Establish two or three recurring layout rails.
- Treat templates as starting points, not finished design.
- Make the hero both clear and visually strong.
- Make design moves either bold or subtle.
- Avoid weak middle-ground composition.

## Mistakes To Avoid

- Starting in Figma before understanding business goals.
- Choosing trendy colors/fonts without conceptual reason.
- Dumping content as raw paragraphs.
- Letting the grid create a boring layout.
- Creating more than three competing focal layers.
- Making every section visually different.
- Leaving large white areas unmanaged.
- Stopping at the first decent version.
- Designing each section independently with no global rails.
- Treating templates as the final design.
- Making heroes that look good but do not explain the offer.
- Making timid layout decisions that feel accidental.

## Strongest Principle

Advanced layout is not chaos.

It is controlled intentionality:

> Every section should feel like someone decided exactly why it looks that way.
