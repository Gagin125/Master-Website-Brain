# Don't Make Me Think - Extracted Principles

Source: Steve Krug, *Don't Make Me Think*

Extraction quality: usable. The PDF text extraction was strong enough to identify the main usability principles.

## Core Idea

The best website interaction is obvious. Users should not have to pause, decode, or wonder what something means before they can move forward.

For website work, this means design must reduce thinking at the exact moments where users decide:

- where am I?
- what is this?
- what can I click?
- what should I do next?
- can I trust this?

## Key Principles

### 1. Make the page self-evident when possible

A user should be able to glance at a page and understand its purpose.

If the page cannot be self-evident, it should at least be self-explanatory.

Website translation:

- the hero should answer what, who for, and why it matters
- buttons should clearly describe the action
- navigation labels should be normal enough to understand
- interactive elements should look interactive
- decorative elements should not look like inactive buttons

### 2. Users scan; they do not read carefully

Users usually scan for useful words, visual anchors, images, prices, location, proof, or the next reasonable action.

Design implication:

- use strong headings
- use short paragraphs
- create clear visual hierarchy
- break pages into visible sections
- avoid long undifferentiated text blocks
- make important facts impossible to miss

### 3. Users satisfice

Users often click the first reasonable option instead of studying every option.

This means:

- the first reasonable path must be good
- primary CTA must be obvious
- navigation should not create competing paths
- duplicate CTAs with the same job can create noise

### 4. Conventions are useful

Users like conventions because conventions reduce thinking.

Examples:

- logo goes home
- navigation sits near the top
- buttons look like buttons
- underlined/clearly styled text can indicate links
- language switchers should be understandable
- menus and contact info should follow familiar structure

Breaking conventions is only worth it when the gain is greater than the confusion.

### 5. Make clickable things obvious

Users should not wonder if something can be clicked.

Avoid:

- pill badges that look like buttons but do nothing
- cards that look clickable but are not
- text links styled like body copy
- buttons with vague labels
- hover-only meaning on mobile

### 6. Navigation answers three questions

Good navigation helps users know:

- where they are
- where they can go
- how to get back

This applies especially to:

- homepage navigation
- gallery pages
- menu pages
- mobile menus
- language switching

### 7. Homepages carry too many jobs

A homepage often needs to introduce the brand, explain the offer, guide users, build trust, and send people to key actions.

This makes prioritization critical. The homepage should not try to give equal visual weight to everything.

### 8. Usability testing does not need to be elaborate

Small tests reveal obvious problems.

For AI-assisted web design, this means:

- inspect desktop and mobile
- click every CTA
- test language switching
- test menu/gallery pages
- check if users would know what to do next
- record obvious confusion points instead of defending the design

## Website Translation

### Hero sections

Good:

- clear headline
- visible primary action
- no decorative confusion
- visual reinforces the brand

Bad:

- poetic but unclear headline
- multiple equal CTAs
- tiny text over busy media
- no clear next step

### Menus

Good:

- categories are scannable
- prices align clearly with items
- active tab is obvious
- full menu behavior is predictable

Bad:

- category labels too many to fit
- product and price visually disconnected
- text size changes when expanding
- tabs look inconsistent across languages

### Contact sections

Good:

- address, hours, phone, email, socials are grouped clearly
- map is paired with useful action
- "Directions" link does what it says

Bad:

- information scattered across the section
- social links styled in a way that fights the design
- buttons placed far from the related content

### Reviews

Good:

- review source is clear
- quotes are short enough to scan
- user can click through to the original review source
- translated reviews are marked

Bad:

- fake-looking review cards
- generic icons that reduce trust
- too many reviews shown at once

## Common AI Website Mistakes

- using clever navigation labels instead of clear ones
- adding badges that look clickable but are not
- making every section visually equal
- writing copy as if users will read every paragraph
- hiding the main CTA under decoration
- changing language visually but not in URL or document language
- designing desktop first and hoping mobile survives

## Candidate Rules For The Brain

- Do not make the user think at decision points.
- Users scan first and read only if interested.
- Buttons should describe the result of clicking.
- Interactive elements must visually behave like interactive elements.
- Use conventions unless breaking them clearly improves the experience.
- The first reasonable action path should be the correct one.
- Test by watching what feels confusing, not by defending the design.

## Rules Not To Overgeneralize

- Do not make every website boring in the name of clarity.
- Do not reject all unconventional layouts.
- Do not assume shorter is always better if users need detail.
- Do not remove brand personality just because conventions matter.
